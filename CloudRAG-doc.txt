# CloudRAG AI

## Free-First Multilingual RAG Application Using Azure OpenAI

**Project type:** AI / LLM / RAG / Cloud Computing
**Primary goal:** Build a production-style document question-answering application using RAG and Azure OpenAI while keeping development costs as close to $0 as possible.

**Target developer:** University student / beginner-to-intermediate AI developer

**Primary development environment:** Windows + VS Code

**Development philosophy:** Local-first, cloud-aware, cost-controlled

---

# 1. PROJECT OVERVIEW

CloudRAG AI is a multilingual document intelligence application.

Users can upload documents such as:

* PDF
* TXT
* DOCX

The application processes those documents and allows users to ask questions about their contents.

The system retrieves relevant document passages and gives them to an LLM before generating an answer.

The fundamental architecture is:

User
↓
Web Application
↓
Backend API
↓
Document Processing / Query Processing
↓
Embedding
↓
Vector Search
↓
Relevant Document Chunks
↓
RAG Prompt
↓
LLM
↓
Grounded Answer
↓
Citations / Sources

The application should support:

* English
* French
* Arabic

The system must prioritize information contained in the user's documents rather than relying on the model's general knowledge.

# 15. CHUNKING STRATEGY

Do NOT blindly use arbitrary chunks.

Start with:

chunk size:
approximately 500–800 tokens

overlap:
approximately 50–100 tokens

Then evaluate.

For PDFs with clear sections, preserve:

* headings
* paragraphs
* page numbers

The system should never destroy useful document structure unnecessarily.

# 18. RAG PROMPT

The LLM should receive a strict instruction.

Conceptually:

SYSTEM:

You are a document-grounded AI assistant.

Answer the user's question using the provided context.

Rules:

1. Use the supplied context as the primary source.
2. Do not invent information.
3. If the context does not contain enough information, say so.
4. Do not pretend that unsupported information comes from the documents.
5. Cite the relevant source documents.
6. Answer in the language requested by the user.

CONTEXT:

[retrieved chunks]

USER:

[user question]

---

# 19. HALLUCINATION CONTROL

The application must explicitly handle insufficient evidence.

If retrieval is poor:

DO NOT:

"The answer is definitely..."

Instead:

"I could not find enough information in the uploaded documents to answer this reliably."

This behavior is one of the most important parts of the project.
